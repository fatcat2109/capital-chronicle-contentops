## 0. Objective

Finish one coherent Capital Chronicle distribution-and-learning product without restarting historical hardening programs or building parallel authority stacks.

The final architecture is:

`Capital Chronicle intelligence/data authority -> ContentOps intelligence fusion -> V1 publishing + V2 video/media -> observation -> bounded learning -> audience/business utility`.

The immediate product problem is not lack of database discovery or lack of media infrastructure. It is that the strongest foundations are not yet connected end to end with enough real governed utilization, source reachability, final live acceptance, and measurable audience/business feedback.

## 3. Final architecture and authority boundaries

### 3.1 Capital Chronicle intelligence/data authority

Capital Chronicle remains authoritative for proprietary calculations, numeric truth, scenarios, probabilities, forecasts, regimes, analytical conclusions, prospective scoring, realized outcomes, and analytical error attribution.

ContentOps is read-only toward that authority. No ContentOps model or heuristic may create missing CC numeric truth.

### 3.2 ContentOps intelligence fusion

For each credible current candidate, the fusion layer should combine:

- current headline/event discovery;
- latest accessible public evidence;
- published-memory/update-chain context;
- relevant read-only CC context/discovery;
- exact governed CC authority packets where applicable;
- rights-safe visual/data opportunities;
- current portfolio/performance signals that affect priority/packaging only.

### 3.3 V1 publishing

One canonical V1 runtime owns newsroom state, article/package production coordination, publication, readback/reconciliation, observation scheduling, and recovery. No parallel newsroom/store/publisher is authorized.

### 3.4 V2 media

V2 is a downstream isolated factory. It never creates or mutates V1 publication/runtime authority. It consumes a qualified governed story package and returns media/package artifacts plus deterministic/creative QA evidence.

### 3.5 Observation and bounded learning

Observation records what actually happened. Learning proposes bounded changes to priority, timing, packaging, SEO, hooks, assets, and creative policy. It never changes factual/numeric/permission authority.

## 4. Capital Chronicle Intelligence Utilization 2.0

This is the first implementation capability after this authority cleanup.

### 4.1 Problem

Current production evidence can show:

`14 stores discovered -> 176 candidate tables -> 8 schema-relevant tables ranked -> 0 tables actually queried`.

The principal observed cause is weak/empty story semantics (`entities_topics=[]`) before story-scoped query execution. A newer zero-write rehearsal path includes a headline-text fallback, but current qualification/preselection evidence still proves underactivation in the main story-selection flow. The solution is to fix the shared semantic/query/use path rather than rely on a rehearsal-only fallback.

### 4.2 Semantic activation

Before bounded CC querying, each candidate should deterministically or safely derive a normalized query context where evidence supports it:

- entities and institutions;
- countries/regions;
- sectors/industries;
- asset classes/instruments;
- economic concepts/data releases;
- event/policy type;
- historical-comparison questions;
- transmission/cross-asset questions.

The semantic activator does not grant factual authority. It only creates query intent. Preserve exact source fields from which the semantics were derived.

If meaningful semantics truly cannot be established, record a zero-use reason rather than forcing a query.

### 4.3 Bounded relevant querying

Reuse current estate discovery and deterministic schema ranking. Do not query everything.

Recommended behavior:

1. refresh/fingerprint current estate;
2. rank relevant candidate tables from current schema;
3. select a bounded number of tables based on story semantics and schema compatibility;
4. execute read-only point-in-time/story-scoped queries;
5. return compact matched context and quality/freshness metadata;
6. record exactly why a selected table was or was not queried/matched.

Protect request/runtime budgets and fail that capability only when a store/table is stale, incompatible, or unavailable.

### 4.4 Context vs governed authority

Never merge these classes.

**Context/discovery bundle** may include compact historical/entity/event/document matches and dataset pointers. It grants zero factual/numeric publication authority unless independently supported by accepted external evidence or an exact governed CC packet.

**Governed authority bundle** must remain exact-story-bound, permissioned, fresh enough for its declared use, and lineage/DQR-preserving. It may contain approved proprietary numeric/analytical claims only within explicit scope.

### 4.5 Point-in-time, lineage, DQR, and schema compatibility

Preserve where available:

- `known_at`;
- `as_of`;
- source/event/observation/revision times;
- estate/catalog/schema fingerprint;
- packet, source, series, calculation, model/run identity;
- evidence refs and citations;
- DQR/source-health/freshness;
- permission state;
- observed/forecast/scenario classification.

A stale/incompatible governed surface should return a bounded compatibility blocker such as `CC_GOVERNED_SURFACE_COMPATIBILITY_REQUIRED`, not veto an unrelated ordinary factual article.

### 4.6 Shared governed chart/data interface

Implement one safe V1/V2 chart-data contract instead of a separate V2 analytical store.

Minimum packet fields:

- packet/chart/series/calculation IDs;
- exact story binding;
- `known_at`, `as_of`, observation/source/revision time;
- observed vs forecast vs scenario state;
- units and transformation;
- values or safe display projection;
- provenance/evidence refs;
- DQR/freshness/source health;
- rights/reuse/public-display permission where relevant;
- schema/version/fingerprint;
- `llm_numeric_authority=false`.

V1 can use it for article charts, historical comparisons, regime/cross-asset context, and scenario framing. V2 can use the same packet for analytical maps, charts, timelines, and visual evidence.

### 4.7 Utilization telemetry

Persist compact per-candidate/per-run telemetry:

- CC estate/catalog fingerprint;
- stores discovered;
- tables discovered/candidate count;
- ranked/selected tables;
- actual queried tables;
- matched stores/tables;
- match count/context richness;
- governed packets found;
- governed packets used;
- governed packets rejected stale/incompatible;
- chart/data packets found/used;
- semantic activation inputs/output;
- zero-use reason;
- read-only/upstream-mutation proof;
- query elapsed time/budget.

The UI must eventually answer: "What relevant Capital Chronicle intelligence did this story actually use, and why?"

### 4.8 Acceptance

A real zero-write vertical slice should cover at least four distinct current story classes (for example macro release, policy/central-bank, company/technology, geopolitical/event) and prove:

- relevant stories produce meaningful semantic query intent;
- selected tables are actually queried when justified;
- irrelevant stories may correctly use zero CC;
- context never silently becomes governed authority;
- at least one available governed numeric/analytical packet is consumed end to end when an exact current story supports it;
- at least one governed chart/data packet is consumable by both V1 and V2 adapters without value regeneration;
- stale/schema-incompatible surfaces fail boundedly;
- no upstream mutation and no model-created numeric substitution;
- telemetry truthfully explains every zero-use case.

## 5. Latest-web evidence/source resolver

### 5.1 Problem

Recent canaries show source acquisition failing due to unavailable embedded URLs, missing publish timestamps, insufficient bound source bytes, and request-budget exhaustion.

### 5.2 Direction

For each high-ranked candidate, prefer:

`candidate -> current locator/search/research -> accessible primary source -> strong accessible professional secondary where needed -> normalized exact source record -> evidence packet`.

Do not treat the discovery URL embedded in an X/feed item as the only possible evidence route.

No login/paywall/anti-bot bypass. Never upgrade snippets/model summaries into source authority.

### 5.3 Acceptance

- accessible primary sources are preferred when known;
- bounded secondary recovery is available when primary delivery is unavailable and policy permits;
- source identity, URL, publish/known time, content hash, authority class, and permission are preserved;
- blocked source delivery is distinguished from an unverifiable story;
- request budgets are candidate-aware so one brittle source does not exhaust the whole publishability walk;
- minimum trustworthy evidence remains fail-closed.

## 6. V1 final acceptance

After CC Utilization 2.0 and source-resolution blockers are corrected, run one fresh canonical V1 live acceptance path.

Required sequence:

1. recover/reconcile any prior obligations;
2. ingest current headlines and build the real current candidate universe;
3. rank/qualify with latest-web + relevant CC intelligence;
4. abstain if no story is strong enough;
5. when a qualified article exists, invoke exactly the current owner-authorized editorial worker boundary;
6. deterministic factual/numeric/rights/reader-value validation;
7. purposeful article media, including zero images when preferable;
8. verify exact readiness for Substack plus all eight V1 derivative destinations;
9. canonical Substack-first publication;
10. attempt every required derivative under exact destination identity;
11. read back/reconcile every public object;
12. require `UNKNOWN_WRITE=0` and no ambiguous pending reconciliation;
13. schedule supported observations;
14. Jim/ChatGPT inspect the actual public article and derivative artifacts.

A legitimate `NO_PUBLICATION` proves safe abstention but is not final publication canary proof.

After an accepted real canary, enable only the already-authorized current four V1 tasks and prove unattended/cold-start operation before `V1_FINAL_PRODUCT_ACCEPTED`.

- source reachability/freshness;
- article/media state;
- nine-surface readiness/publication;

Unsupported lanes display unavailable, never fake healthy/zero values.

## 8. V2 final creative factory and soak

Continue from the current accepted creative-authority architecture rather than rebuilding it.

Canonical flow:

`qualified governed story -> institutional analytical map -> evidence expansion -> visual entity/asset needs -> fresh rights-safe asset board -> visual-fit selection -> story-specific free-form Remotion source -> short + justified longform -> professional audio -> final-audio-bound transcript/package -> deterministic hard-boundary QA -> actual-media XHIGH/owner review -> bounded localized repair -> owner master`.

Key acceptance:

- viewer-facing source remains story-specific rather than fixed-template substitution;
- concrete evidence/assets dominate over generic abstract visuals;
- charts/data are governed and legible, with full-chart holds when the whole chart matters;
- asset-family repetition is controlled qualitatively, not by file-count quotas;
- picture/audio caching and localized repairs work without unnecessary full rerenders;
- repeated unattended jobs recover safely;
- actual media is owner-accepted;
- measured TCO/runtime stays bounded;
- no video public write.

## 9. V1 -> V2 qualification loop

Do not produce a video for every article.

A shadow scorer should combine only supported signals:

- real V1 story usefulness/performance;
- evidence and analytical depth;
- visual/rights-safe asset supply;
- narrative shelf life;
- portfolio novelty/repetition;
- expected production cost/time.

Output: `QUALIFIED`, `DEFERRED`, or `ABSTAIN`, with reason codes. Engagement may change priority but cannot create evidence or CC authority.

## 10. Publication/readback beyond V1

Any future V2 platform publication must be separately owner-authorized by exact destination/account, public-object type, visibility, provider/browser boundary, recovery policy, and readback contract.

No provider adapter or credential existence is publication authority.

A successful future write counts only after exact public-object identity/content readback and reconciliation. Unknown result always stops retries until readback.

## 11. Retention attribution and video learning

After a real eligible public cohort exists, collect supported platform-native metrics such as completion, retention curve, rewatch, share, save, click/subscriber effects where APIs/authorized observation permit.

Bind metrics to exact media/package/public-object identity and scene/beat ranges where trustworthy. Learning may suggest hook, pacing, asset, chapter, package, or qualification changes. It cannot rewrite past factual evidence or change CC outputs.

## 12. Closed learning and business funnel

Long-term observation should connect content identity to supported acquisition/conversion outcomes:

`article/video -> landing/signup -> returning user -> beta/product use -> paid -> retained`.

Do not overfit small samples. Low-confidence learning should produce no-op or bounded recommendations.

The business objective is lower cost and higher quality of acquiring, educating, converting, and retaining Capital Chronicle users — not maximizing content volume or automation ceremony.

## 14. Anti-overengineering and exact deferrals

Do not build before direct product need:

- a second CC database or broad mirror;
- query-all-table behavior;
- a separate V2 analytical engine;
- a new newsroom/store/publisher/scheduler authority;
- broad multi-agent role expansion;
- arbitrary model bakeoffs;
- a second dashboard/control plane;
- deterministic aesthetic quotas pretending to equal quality;
- full historical backfills unrelated to current story utility;
- broker/live execution;
- video public-write expansion before exact owner grant;
- autonomous public replies/DMs;
- broad security/compliance ceremony not tied to a real product blocker.

Prefer one implementation, one independent audit, and at most one bounded correction.
