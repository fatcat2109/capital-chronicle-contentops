## Permanent obligation and current model

Every V1 article must receive actual final rendered-media review before publication.
The currently required native editor/reviewer is **GPT-6.1 Sol MAX**:
`gpt-6.1-sol`, reasoning effort `max`. The same MAX writer/editor owns direct repairs.
This obligation applies to owner-manual and scheduled production, canonical articles,
their actual derivative media, and later material revisions. It survives completion of
the current goal, future chats, source releases and model upgrades.

A stronger future LLM may replace the active editor/reviewer assignment through the
existing editorial model policy and configuration. Change that assignment consistently;
retain this review, repair, revision-binding and publication-enforcement obligation.
Retain the actual historical model provenance. A model upgrade does not retroactively
change an old review or excuse a missing current review. Quota or unavailability does
not permit an unannounced weaker model, effort downgrade or skipped visual inspection.

## Inspect the finished product

The assigned MAX editor must inspect the actual final rendered article and every image,
chart, graph and other included visual, with the relevant desktop/mobile presentations.
Inspect affected channel crops, subsets and layouts; reuse an unchanged inspection only
when the actual visual and its relevant presentation remain unchanged.

- Compare plotted values with admitted source data: signs, magnitudes, denominators,
  units/currency, transformations, rounding, dates, years/quarters, series association,
  actual/estimate/forecast labels, missing values and source links.
- Inspect visual meaning: positive and negative directions, a correct visible zero
  baseline where applicable, axis limits/scales, stacks/totals, comparability, chart
  form and whether the visual honestly supports the article's stated claim.
- Inspect readability: labels and legend associations, overlaps, clipping, font size,
  contrast, mobile cropping, aspect ratio and final placement in the article.
- Inspect photographs and other media: identity, relevance, contextual/archive date,
  caption, credit, alt text, source and lawful reuse. An archive photo is context;
  it does not independently establish the article's news claim.

Existing substantial-analysis requirements for 2–5 distinct useful source-grounded
charts and justified narrow-news/policy exceptions remain. A chartless story still
requires review of its other media. Do not add decorative charts to satisfy a count.
Chart planning, code tests, a model-setting label and a written claim of inspection
cannot substitute for the actual MAX inspection of the final rendered output.

## Repair the same product before sending

When a defect is found, the same MAX editor directly fixes the affected article/media
using the existing source, computation, code, rendering and editing tools. Code owns
numeric computation and rendering; MAX owns the editorial correction and its review.
Re-render the affected outputs, inspect the correction and continue the same article.
Preserve valid sources, intake/filter results, writing, assets and unaffected reviews.

Do not discard a product, switch stories or restart the pipeline to avoid an ordinary
correctable defect. An arbitrary one-repair limit must not end necessary corrections.
Use specific findings to guide corrections; do not repeat blind retries or broad audits.
Quota/context interruptions retain the same operation and exact pending repair.
Use the existing legitimate revision path; never alter frozen hashes to bypass checks.

A genuine missing source, reuse right or access dependency remains explicit. Preserve
the article and exact affected work/resume condition; repair defensibly and continue
independent usable work. Do not invent data, conceal uncertainty or publish a known error.

## Enforce through existing publication owners

Record the actual review and correction result in the existing revision-bound review
and native request/return records. Bind it to the exact article revision, media bytes,
relevant rendered outputs and observable native model/effort/invocation provenance.
The existing publication owner must reject a fresh send when this acceptance is absent,
stale, from the wrong active model/effort, or contains unresolved material findings.

A material copy, data, media or layout change invalidates affected acceptance. Obtain
the required MAX correction/review for that revision before sending. A failed review
keeps the same product resumable for repair; it does not create a discard/restart route.
Reuse the sole DurablePublicationCoordinator, current store/outbox/reviews and four
existing schedules. UNKNOWN_WRITE retains STOP RETRY -> READ BACK -> RECONCILE.
Do not create a second reviewer fleet, approval ledger, scheduler or publisher.

Current authority documents, North Star, Master Plan, editorial role policy, generated
routine prompts and installed publication checks must carry this permanent requirement.
Saving this contract establishes the durable instruction; installed enforcement and
actual reviews must be reported separately with their real implementation evidence.
