## 3. What the A/B proved

### 3.1 Both lanes are a major advance over R4

The replacement architecture solved the central R4 failure mode: viewers no longer have to decode an invented symbolic visual language before understanding the story.

Both lanes moved toward:

- recognizable geography;
- real/contextual tanker and infrastructure imagery;
- primary EIA documents;
- native chart treatments;
- physical oil-flow mechanisms;
- explicit forecast-versus-observation boundaries;
- narration-linked motion;
- concrete-first visual grounding.

This validates `CONCRETE_FIRST_ABSTRACT_SECOND` as a durable V2 doctrine.

### 3.2 Lane A result

Lane A proved that `cx/gpt-5.6-sol(xhigh)` can successfully author the controlled benchmark through a 9Router route when the `new/...` route was operationally unreliable for large creative outputs.

Lane A strengths:

- low direct model cost relative to Lane B;
- evidence-grounded Director and semantic segment authorship;
- generated Remotion motion code with provider provenance;
- strong analytical density;
- good native document/chart handling relative to R4;
- potentially attractive economics if visual quality can be raised mostly through deterministic infrastructure.

Lane A weaknesses observed in the actual masters:

- subtitle layer creates visual clutter and unnecessary information density;
- some scenes still contain weak alignment, annotation-box, framing, and source-rail decisions;
- repeated background/documentary assets create visual fatigue;
- text-heavy scenes can become analyst-dense rather than social-retention-native;
- visual hierarchy is less consistently polished than the strongest Lane B scenes;
- the route and schema required compatibility/projection work that should be formalized rather than repaired ad hoc.

Lane A remains strategically useful as:

1. a low-cost creative-brain benchmark;
2. a shadow comparison lane;
3. a possible future production brain if it can drive the shared Lane B Hybrid visual engine at materially lower marginal cost without losing quality.

Lane A is **not** the canonical V2 final-media architecture after this decision.

### 3.3 Lane B result

Particularly strong visual/editorial patterns include:

- `ONE CHOKEPOINT. FOUR TESTS.` as a clear short-form narrative promise;
- orbital geography into `MapToVessel`;

- native direct-label forecast chart;
- a short, explicitly disclosed illustrative transmission scene;
- conditional consequence cards;
- `CONFIRM IF / CHALLENGE IF` thesis-testing language;
- a checkpoint/timeline close that preserves observation-versus-forecast boundaries.

The owner judged the latter half of Lane B to be close to publishable quality. The strategic target is therefore not merely to clean isolated bugs; it is to make **the entire Lane B video consistently as strong as its best second-half scenes**.

Lane B weaknesses observed in actual media and iteration history:

- early scenes previously required multiple crop/matte/layout corrections;
- some visual/source systems were corrected only after actual pixel review;
- repeated storage/infrastructure imagery remains a weakness;
- some midform scenes hold too long for cold-audience retention;
- the current controlled proof does not yet have enough institutional analytical depth for the final product ambition;
- the A/B proof required too much interactive builder iteration to qualify as a durable unattended daily production system.

The conclusion is therefore **not** “run the current full-Codex proof manually forever.” The conclusion is to preserve Lane B's creative ceiling while removing its operational fragility and repeated manual repair through a reusable local product architecture.

## 4. Canonical architecture decision: Lane B Hybrid

### 4.1 Codex is the creative brain, not the control plane

Codex owns high-entropy creative/editorial decisions where its ability to inspect, reason, code, and revise materially improves viewer value:

- story-angle selection within an already qualified article;
- institutional analytical decomposition;
- narrative architecture;
- hook and re-hook strategy;
- narration;
- controlled financial wit;
- visual storytelling strategy;
- asset-to-purpose decisions;
- storyboard and scene strategy;
- novel scene composition;
- novel motion code where no safe primitive fits;
- visual inspection of proxy/full media;
- localized creative revisions.

Codex does **not** become durable truth authority, scheduler authority, publication authority, or the only persistence mechanism.

### 4.2 Deterministic local V2 engine owns durable execution

The local/headless V2 engine owns:

- V1 -> V2 candidate event intake;
- durable outbox/job queue;
- job IDs and immutable checkpoints;
- evidence and numeric authority bindings;
- rights/provenance manifests;
- asset acquisition contracts;
- institutional design tokens;
- typography/safe-zone rules;
- reusable scene primitives;
- chart/map/document compilers;
- layout measurement/collision prevention;
- caption policy;
- asset-diversity policy;
- TTS/music/SFX tool execution;
- Remotion rendering;
- deterministic technical QA;
- cache/selective rerender;
- stage-level retries and resume;
- cost/runtime telemetry;
- package finalization;
- public-write gate and destination authority.

### 4.3 No persistent 24/7 Codex conversation

A permanent long-lived Codex session is not production architecture.

Reasons:

- context drift;
- stale assumptions;
- session corruption or desktop restart risk;
- weak reproducibility;
- unclear partial-write ownership;
- poor per-video cost accounting;
- difficulty proving exact creative provenance;
- accumulated irrelevant context.

Canonical operating model:

**one fresh isolated Codex execution/thread per qualified video job, with immutable input packets and durable stage checkpoints.**

The run may resume its own thread for bounded revisions within that one video job, then terminate when the final package is complete or the job fails/abstains.

## 5. North-star product outcome

V2 is not a slideshow generator and not a generic financial-news recap tool.

V2 must become an autonomous evidence-governed media growth engine that converts the strongest V1 articles into retention-native Capital Chronicle video products with:

- institutional analytical depth;
- clear causal mechanisms;
- primary evidence and hard data;
- strong visual comprehension without captions;
- editorial motion rather than decorative motion;
- premium, recognizable Capital Chronicle visual identity;
- conversational pacing;
- calibrated financial wit;
- explicit uncertainty and thesis-testing;
- rights-safe purposeful media;
- repeatable low-operator production;
- bounded measurable cost;
- post-publication learning that improves packaging without changing truth.

The product should feel like a sharp institutional macro desk that also understands modern social video craft.

## 6. Institutional editorial engine

### 6.1 Three-layer separation

Every V2 script and scene plan must preserve three distinct layers.

#### Truth Layer

Contains only authorized factual material:

- observations;
- source-backed historical facts;
- primary-source statements;
- dated forecasts;
- exact numeric authority;
- explicit evidence references;
- uncertainty/status.

This layer cannot be modified for engagement.

#### Analytical Layer

Contains Capital Chronicle reasoning that may explain:

- physical mechanisms;
- first-order market transmission;
- secondary transmission channels;
- balance-sheet effects;
- fiscal/external-account effects;
- rates/FX/inflation consequences;
- supply substitution;
- positioning/pricing implications when authorized;
- countervailing channels;
- scenarios;
- confirmation and invalidation conditions.

Capital Chronicle-owned numeric/probabilistic conclusions still require exact Capital Chronicle authority. Codex may organize and explain them but may not invent them.

#### Engagement Layer

Contains packaging only:

- conversational phrasing;
- hook/re-hook;
- pacing;
- analogy;
- contrast;
- concise rhetorical questions;
- controlled wit.

Engagement may change presentation and priority, never factual/numeric truth.

### 6.2 Institutional Analytical Spine

Every midform candidate should answer, when supported by the story:

1. What changed?
2. What has not changed yet?
3. What is the physical or institutional mechanism?
4. What is already priced or widely expected, if there is authority for that statement?
5. Who gains, loses, or bears the balance-sheet effect?
6. What are the most important second-order transmission channels?
7. What evidence would confirm the thesis?
8. What would challenge or invalidate it?
9. What is the next observation window or calendar checkpoint?

Not every story needs every channel. The creative brain should choose the two to four analytical channels with the greatest marginal explanatory value.

### 6.3 Analytical channel library

The engine should gradually support domain-specific channel packs rather than one generic macro template.

Energy/oil examples:

- physical shipping and chokepoints;
- terminal/unloading constraints;
- production restart;
- inventories;
- spare capacity;
- freight and insurance;
- refining and crack spreads;
- futures curve versus spot;
- producer cash flow and fiscal breakevens;
- importer trade/current-account effects;
- gasoline and inflation transmission;
- rates/FX consequences;
- substitution and demand response.

Other future packs may cover:

- central banks/rates;
- inflation;
- labor;
- fiscal policy;
- housing;
- semiconductors;
- shipping;
- elections/policy;
- commodities;
- credit/liquidity;
- corporate balance sheets.

### 6.4 Density budgets

#### Short, roughly 45–60 seconds

Aim for:

- one core question;
- one primary mechanism;
- roughly two strong hard-data/evidence anchors;
- one second-order implication;
- one counter-case or uncertainty boundary;
- one watch condition;
- zero or one controlled wit line.

A short should not attempt to compress the full institutional brief.

#### Midform, roughly 90–150 seconds

Aim for:

- one core thesis/question;
- two to three mechanism layers;
- roughly three to five hard-data/evidence anchors;
- physical + financial + macro transmission when supported;
- one meaningful counter-case;
- pricing/positioning distinction only when evidence exists;
- three to five confirmation/watch signals;
- at most two to three controlled wit lines.

### 6.5 Conversational, not academic

Narration should prefer tension and questions over textbook section labels.

Preferred rhythm:

- “Movement is back. Is supply back?”
- “What has to happen between a ship crossing Hormuz and an actual barrel reaching inventory?”
- “What is the market assuming before the data confirms it?”
- “What would prove this wrong?”

Avoid lecture framing such as:

- “First we examine the physical channel.”
- “Second we examine the macroeconomic consequences.”

### 6.6 Controlled financial wit

V2 may use dry, subtle, domain-aware financial wit when it improves retention without weakening institutional tone.

Good pattern:

- short deadpan observation;
- tied directly to mechanism;
- understandable to a financially literate viewer;
- optional rather than mandatory.

Examples of desired tone, not reusable mandatory copy:

- “Markets can price a reopening in minutes. Inventories are less cooperative.”
- “Forecasts travel faster than crude.”

Hard restrictions:

- no meme slang as a default voice;
- no cheap jokes;
- no humor around casualties/human suffering;
- no new factual claim created for the joke;
- no humor inside primary-document/evidence presentation;
- no implication of buy/sell/hold advice;
- no joke density that reduces trust.

Recommended process:

`Analytical Script -> Wit Candidate Generator -> Truth/Relevance/Tone Validator -> zero to N accepted lines`

## 7. Visual product doctrine

### 7.1 Concrete first remains mandatory

Visual priority:

1. real documentary/context media;
2. primary evidence/document;
3. native map/chart/data visual;
4. concrete explanatory illustration;
5. abstract explanatory diagram/metaphor.

Abstract visuals should explain invisible mechanisms, not substitute for readily available real-world context.

### 7.2 Lane B design language becomes the positive reference

The current Lane B proof is a positive reference for patterns, not a frozen template.

Promote the strongest structures into reusable primitives:

- `MapToVessel`;
- `PhysicalChain`;
- `DocumentEvidence`;
- `NativeForecastChart`;
- `Transmission`;
- `Consequence`;
- `ConfirmChallenge`;
- `CheckpointTimeline`.

These primitives provide safe composition and motion structure, but should remain parameterized and composable so every video does not look identical.

### 7.3 Central visual safety compiler

The system must eliminate the failure pattern where native asset text, model-authored text, source rails, and captions independently occupy the same pixels.

For every source asset, capture where feasible:

- native text regions;
- native logo/source regions;
- important focal-object bounds;
- recommended crops by aspect ratio;
- forbidden overlay regions;
- semantic labels already present in the asset.

The layout system should own:

- title region;
- body region;
- source region;
- caption region;
- annotation region;
- z-order;
- measured text bounds;
- safe-zone validation.

Model/Codex creative intent may request emphasis, but routine text geometry should be resolved by safe primitives and measured layout rather than arbitrary absolute positions.

### 7.4 Document compiler

Primary-document scenes require a dedicated compiler/component.

Requirements:

- source/date remain visible;
- relevant excerpt is readable;
- one semantic highlight at a time by default;
- highlight geometry derives from known/measured excerpt regions, not guessed rectangles;
- no duplicate native + overlay headers;
- source rail may not cover native source identity;
- forecast/result or equivalent semantic boundary remains clear;
- documents must be native to 9:16 and 16:9, not naïvely letterboxed.

### 7.5 Chart compiler

Charts must be generated from structured data when possible.

Requirements:

- direct labels;
- phone-readable type;
- minimal legend dependence;
- explicit observation versus forecast styling;
- selected windows rather than full-history chart dumps;
- native 9:16 and 16:9 composition;
- semantic animation such as reveal/comparison, not endless chart crawl.

### 7.6 Caption policy

The default editorial master should be clean rather than permanently burning a large subtitle card into every frame.

Produce:

1. clean master;
2. sidecar/platform captions;
3. optional social-caption derivative.

Social caption derivative requirements:

- at most two lines;
- bounded screen occupation;
- no duplicate headline text;
- automatically disabled or repositioned on text-heavy document/chart scenes;
- platform safe-zone aware.

### 7.7 Asset diversity policy

The current A/B proof repeated storage/infrastructure imagery too often.

The future asset broker must track:

- reuse count;
- cumulative screen time;
- semantic role reuse;
- consecutive background reuse;
- near-duplicate candidate similarity.

Initial design target:

- one asset should normally not dominate more than roughly 15% of visual screen time without explicit motif justification;
- avoid consecutive scenes using the same background asset;
- major repeated assets should have a genuinely different semantic purpose/crop;
- candidate universe should include alternates for the dominant physical concepts.

These are starting heuristics, not immutable product laws; actual viewer-performance evidence may tune them.

### 7.8 Motion doctrine

Motion serves information.

Preferred:

- semantic cuts;
- evidence reveal;
- map progression;
- physical-chain sequencing;
- line/data drawing;
- state change;
- comparison;
- purposeful reframe;
- controlled hold.

Avoid:

- constant parallax;
- unrelated simultaneous animation;
- repeated generic easing everywhere;
- title-card slideshow grammar;
- motion used merely to keep pixels moving.

## 8. V1 -> V2 daily operating loop

### 8.1 V1 remains the canonical article engine

V1 continues to publish useful qualified articles. The current portfolio target may be around 5–8 useful articles/day, never filler permission.

### 8.2 Video candidacy is conditional

V2 does not blindly convert every article.

A candidate requires both:

- sufficient V1 engagement/performance quality;
- sufficient video opportunity.

No-publication/no-video is valid.

### 8.3 Engagement qualification

Potential inputs include:

- unique readers;
- read/completion depth;
- dwell time;
- shares;
- comments;
- saves;
- subscriber conversion;
- performance velocity adjusted for article age.

Engagement signals influence priority/packaging only. They never alter factual or Capital Chronicle numeric truth.

### 8.4 Video opportunity qualification

Potential factors include:

- recognizable visual entities;
- concrete mechanism;
- fresh primary evidence;
- useful hard data;
- rights-safe asset availability;
- secondary analytical consequence;
- narrative tension;
- novelty versus recent videos;
- expected production cost.

### 8.5 Candidate scoring

Initial scoring weights may be treated as calibration hypotheses, for example:

- ~40% engagement quality;
- ~20% velocity;
- ~15% video opportunity;
- ~10% evidence freshness;
- ~10% portfolio diversity;
- ~5% expected production cost.

Do not freeze these numbers as truth before enough real observations exist.

### 8.6 Trigger windows

Possible operating modes:

- early short trigger around 60–120 minutes after publication if an article materially exceeds absolute thresholds;
- later midform/end-of-day trigger after roughly 6–12 hours when ranking is more stable.

Exact windows remain calibration parameters.

The product target is approximately the top one or two truly qualified daily opportunities, not a forced quota.

## 9. Headless unattended execution blueprint

Canonical execution model:

`V1 metrics -> Video Candidate Scorer -> Durable V2 Outbox -> V2 Supervisor -> Fresh isolated Codex job -> Evidence lock -> Editorial engine -> Assets -> Storyboard/proxy -> Codex visual review -> Local compilers/Remotion -> QA -> localized revision -> final package -> owner/publication gate`

### 9.1 Durable states

Recommended job states:

- `DISCOVERED`
- `QUALIFIED`
- `CLAIMED`
- `EVIDENCE_LOCKED`
- `EDITORIAL_READY`
- `ASSETS_READY`
- `STORYBOARD_READY`
- `PROXY_READY`
- `QA_REVISE`
- `MASTER_READY`
- `OWNER_REVIEW`
- `PUBLICATION_ELIGIBLE`
- `ABSTAINED`
- `BLOCKED`
- `FAILED`

Every stage should retain:

- exact input hash;
- output hash;
- tool/model identity;
- sanitized receipt;
- cost/runtime;
- retry count;
- failure class;
- next legal transition.

Machine/process restart resumes from the last valid immutable checkpoint rather than recreating completed expensive work.

### 9.2 Supervisor and scheduler

A local scheduler such as Windows Task Scheduler may wake a small V2 supervisor, but the scheduler must not become the product logic.

Preferred shape:

`Task Scheduler -> run_once supervisor -> atomically claim durable job -> spawn isolated Codex execution -> monitor stage ledger -> finalize/quarantine`

Do not keep a general-purpose Codex conversation alive waiting for events.

### 9.3 Codex execution abstraction

The architecture should expose a stable creative-brain boundary so the implementation can use the best supported headless Codex execution mechanism without coupling the product to a specific desktop conversation.

Conceptual interface:

- `select_angle()`
- `build_analytical_map()`
- `write_narration()`
- `propose_wit()`
- `build_storyboard()`
- `author_novel_scene()`
- `review_proxy()`
- `revise_localized()`

The output of each call is an explicit artifact/checkpoint rather than hidden session state.

## 10. Tool responsibility

- Capital Chronicle/V1 authority: factual/numeric truth and governed article input.
- Codex: high-entropy creative/editorial reasoning and visual review.
- Asset broker: documentary/context assets and rights.
- Image-generation tool: illustrative assets only where justified; never documentary authority.
- Chart/map/document compilers: deterministic evidence-native visuals.
- Voice tool: actual speech waveform generation.
- Codex: voice direction/script, not fabricated claim that Codex itself synthesized audio when a separate tool did it.
- Music/SFX engine: owned/procedural/audio-provider execution.
- Remotion: deterministic composition/rendering.
- Machine QA: technical/legibility/provenance/safety gates.
- Codex multimodal review: visual coherence and localized creative revision.
- Publication coordinator: separate explicit destination/public-write authority.

## 11. Post-publication learning

Once platform-write authority is separately granted and analytics are available, map retention/performance back to creative structure.

Maintain timeline mapping:

`elapsed time -> scene -> beat -> visual primitive -> asset class -> hook type -> analytical channel -> wit presence`

Learning may tune:

- timing;
- beat order;
- hook style;
- visual primitive priority;
- asset selection;
- caption packaging;
- video candidacy thresholds.

Learning may never tune or distort factual/numeric truth.

## 12. Cost/value doctrine

Optimize total cost of ownership, not merely API tokens.

Measure:

`TCO = creative model/Codex cost + media/tool cost + render compute + failed rerenders + operator review time + opportunity cost`

Lane B currently has the higher demonstrated visual ceiling but also higher interactive iteration cost.

The Hybrid architecture exists to preserve that ceiling while reducing marginal cost by:

- moving routine layout into safe primitives;
- fixing compiler bugs once instead of per video;
- selective rerender;
- immutable stage resume;
- using Codex for high-value creative decisions rather than routine mechanics.

Lane A should remain a cost benchmark. After the shared Hybrid engine is hardened, run controlled shadow comparisons to determine whether CX XHIGH can drive the same engine near Lane B quality at materially lower marginal cost.

Do not maintain two independent renderer/visual stacks long-term.

## 13. Acceptance path before publication authority

Current V2 remains zero-video-public-write.

Before unattended public operation, prove the Hybrid engine across multiple real shadow jobs.

Initial acceptance hypotheses:

- roughly 10 consecutive qualified shadow jobs;
- >=90% successful pipeline completion;
- no unresolved MAJOR visual defects;
- most jobs complete without manual source-code edits;
- bounded operator review time;
- measured cost/wall-clock;
- at least one non-oil domain proving generalization;
- consistent quality at or above the strongest current Lane B scenes;
- clean evidence/provenance on every final package.

These are proof targets, not publication authority.
