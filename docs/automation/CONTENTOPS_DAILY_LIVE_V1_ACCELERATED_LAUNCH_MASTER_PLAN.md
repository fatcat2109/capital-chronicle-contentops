## 1. Strategic objective

Launch a useful, evidence-governed Daily Live newsroom as soon as the remaining canonical story/evidence wiring is closed.

Do not interpret launch as completion of every historical platform, schema, UI, source, or hardening ambition.

The objective is repeated real product operation:

```text
fresh current news
→ select / abstain
→ authoritative evidence
→ useful article + native packages
→ deterministic live gates
→ public write where authorized
→ strict readback/reconciliation
→ measured cost and audience response
→ next operating day
```

ContentOps earns qualified attention and distribution. Capital Chronicle supplies differentiated intelligence and remains the only analytical/numeric authority.

## 3. Immediate product blocker

The canonical rolling-X production cycle still must automatically integrate two capabilities that exist separately:

1. story-type classification must be invoked in the normal canonical production cycle rather than relying on an externally injected `story_type_by_cluster` mapping;
2. bounded official-primary evidence acquisition must be available through the default canonical evidence path rather than requiring a task-scoped injected `official_evidence_loader`.

Additionally, evidence requirements must become explicitly **story-type + article-mode aware** so factual reporting is not blocked by analytical requirements that belong only to analysis modes.

This is the last planned architecture correction before Daily Live production probation.

## 4. Work Package DL-A — Canonical story/evidence bridge + fresh canary

Task:

`TASK_CONTENTOPS_DAILY_LIVE_CANONICAL_STORY_EVIDENCE_AND_FIRST_FRESH_CANARY_V1`

Goal:

Close the remaining canonical wiring and run one fresh current governed canary through the full vertical slice.

### 4.1 Required capability

Canonical flow becomes:

```text
rolling-X hierarchical assignment
→ automatic exact story-type routing
→ article-mode selection
→ mode-aware evidence profile
→ capability/source-family acquisition
→ first viable ranked story
→ article / SEO / visuals
→ review / bounded revision
→ native packages
→ deterministic READY_* live gates
→ strict readback/reconciliation
```

### 4.2 Evidence contract correction

Refactor capability resolution so evidence depends on both story type and article mode.

Minimum launch behaviors:

- `regulatory_fiscal_event + straight_news` can be satisfied by authoritative official-document evidence without Capital Chronicle market analysis;
- `company_sector_event + straight_news` can report exact filing/release facts without requiring analytical market interpretation;
- `company_sector_event + analysis` retains the appropriate Capital Chronicle/market authority requirement;
- `data_release + straight_news` can report the official release using exact authorized values/timestamps/definitions;
- `data_release + analysis` retains the required Capital Chronicle analytical/market authority;
- analytical, scenario, forecast, valuation, macro, probabilistic, or market-regime claims always remain Capital Chronicle authority.

No evidence downgrade is permitted. Mode-aware routing separates factual reporting from analytical interpretation; it does not loosen source quality, freshness, permission, or numeric truth.

### 4.3 Launch source families

Implement/reuse only high-utility source families that directly serve the current ranked universe and Daily Live:

- `official_regulatory_fiscal`;
- `company_primary` / `sec_regulatory`;
- `official_macro`;
- existing exact Capital Chronicle market/analysis authority where required.

Do not build broad licensed-news acquisition or every geopolitical/physical source adapter before launch.

### 4.4 Fresh canary

After focused offline validation and commit/push/readback, run one fresh current governed cycle.

Do not reuse stale headlines as if current.

Use the existing persistent Chrome ingestion profile only for the authorized X headline-ingestion lane when a genuinely new current-X universe is needed. Do not read browser session material.

Public writes remain authorized only to exact dynamically verified canonical `READY_AUTHENTICATED` / `READY_NON_BROWSER_BINDING` destinations after all deterministic gates pass.

A valid canary outcome may be:

- public article/packages with strict readback;
- hold/block on exact evidence;
- `NO_PUBLICATION`.

The canary is successful if the canonical product behaves correctly; publication is not mandatory.

## 5. Work Package DL-B — Daily Live probation

Start immediately after DL-A if there is no substantive architecture/runtime blocker.

Duration target:

`5–10 operating days`

Initial cadence:

- one scheduled core editorial decision per day;
- one optional material-event trigger;
- no mandatory publication quota.

Do not automatically open another infrastructure task after the canary.

### 5.1 Daily run record

Each operating day should capture minimally:

- cutoff/window identity;
- candidate and cluster counts;
- selected/held/blocked/no-publication decision;
- story type + article mode;
- evidence source families used/blocked;
- model attempts/tokens/runtime/cost where available;
- article/review/package outcome;
- destination readiness;
- exact public object IDs and readback when writes occur;
- incidents/reconciliation;
- operator intervention minutes;
- initial qualified-engagement observations when available.

This is operational telemetry, not a new documentation program.

### 5.2 Probation acceptance evidence

The goal is to observe:

- repeated successful daily decisions;
- several useful real publications when evidence permits;
- explicit legitimate abstentions;
- more than one story/source type when eligible;
- no unreconciled unknown writes;
- zero fabricated/nonauthorized claims;
- bounded and understandable provider/runtime cost;
- low operator intervention;
- real platform/readback failure modes;
- early audience/subscriber/canonical-click behavior.

## 6. Work Package DL-C — Social platform build in parallel

Capital Chronicle social surfaces are a parallel distribution workstream, not a Daily Live launch blocker.
