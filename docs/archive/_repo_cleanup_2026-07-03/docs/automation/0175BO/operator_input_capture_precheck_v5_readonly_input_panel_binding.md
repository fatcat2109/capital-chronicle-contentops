## Readonly UI Binding Architecture

0175BO projects the 0175BN backend Operator Input Capture Precheck packet into V5 as static TypeScript data:

1. `tools/export_v5_operator_input_capture_precheck_packet.py` loads `docs/automation/0175BN/review_only_intent_to_operator_input_capture_precheck_packet.json`.
2. The exporter renders deterministic TypeScript into `ui/contentops_v5/src/data/operatorInputCapturePrecheckPacket.ts`.
3. `ui/contentops_v5/src/data/operatorInputCapturePrecheckAdapter.ts` exposes typed readonly adapter fields.
4. `ui/contentops_v5/src/selectors.ts` maps packet and item metadata into InspectorRail selectable objects.
5. `ui/contentops_v5/src/views/WriterStudio.tsx` displays a readonly panel.

## WriterStudio Panel Behavior

The `Operator Input Capture Precheck` panel renders:

- global status `BLOCKED_OPERATOR_INPUT_CAPTURE_NOT_ENABLED`;
- source and packet hashes;
- blocked reasons;
- allowed next step;
- next recommended task;
- required input field policy;
- item table for input precheck rows;
- safety flags locked false;
- truth flags locked false;
- disallowed output labels.

Required field policy remains:

| Policy | Value |
|---|---|
| stored value | `PENDING_OPERATOR_INPUT` |
| value status | `PENDING_OPERATOR_INPUT` |
| capture enabled | `false` |
| editable in this task | `false` |
| generated by system | `false` |
| operator must provide later | `true` |
