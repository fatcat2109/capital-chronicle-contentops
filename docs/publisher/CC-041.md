# CC-041: native coordinator continuation

Work and reporting follow the current host instructions and BACKLOG.md. Earlier chat
hierarchies, completion notices and goals in historical source are not authority.
This branch does not change installed schedules or the production pause controls.

Changes:

- Default Luna batches contain up to 96 complete records, with at most three independent
  native calls prepared concurrently. All captured records still require decisions.
- Previously issued smaller batches drain first with their exact request hashes. A
  changed default cannot orphan a pending request or refilter an accepted record.
- Every newly issued role request requires its actual native model and effort at submit.
  Previously issued records retain their historical identities and missingness.
- The CLI's pending result has an explicit same-operation coordinator action. A pending
  native role without a dispatch is a process defect. Unassigned filter records cannot
  become a terminal window. A qualified article still needs its exact final review.
- `consume_advance_result` consumes completed command JSON and requires collection of an
  actual still-running command handle. Empty initial stdout is never an editorial HOLD
  and is never a reason to reissue `advance`.
- New writer prompts include Jim's analysis/not-financial-advice notice. Frozen prompts
  and already issued decisions are preserved.

The continuation helper is deterministic routing information for the native conversation,
not a scheduler or model caller. Python cannot invoke a Codex tool by assertion. A real
role return and an actual reviewed article remain acceptance evidence; passing tests
alone do not release the production kill switch or model pause marker.

## Copied-store replay

`scripts/replay_cc041_native_window.py` works only under the current backlog checkout's
`tests/evidence/cc-041/private-replay/`. `prepare` uses SQLite's read-only online backup of
the existing ContentOps store, reuses its latest whole frozen pool and sets SHADOW_ONLY
on **the copy only**. It never changes Main, the live ContentOps store or a grant. Repeated
preparation checks the same binding instead of starting over.

```powershell
python scripts/replay_cc041_native_window.py prepare --root tests/evidence/cc-041/private-replay
python scripts/replay_cc041_native_window.py filter --root tests/evidence/cc-041/private-replay
```

The parent executes the emitted native role call(s), collects the actual result in its
own operation and uses `submit --stage <exact-stage> --response <actual-response.json>`.
It then resumes `filter` until remaining_unprocessed is zero, followed by `advance`.
The replay preserves the frozen cutoff and exact source records; retained reports and
admitted research resolve through existing evidence adapters. No later source fetch is
backdated into the replay. An uncached source is explicitly blocked, never manufactured.

Raw social captures, model response text and the copied database remain private and
Git-ignored. A sanitized acceptance summary links their exact local evidence. No external
publication, public object identity or live operation is implied by copied-store output.
All pre-existing native goals, user apps and installed automations remain untouched.
