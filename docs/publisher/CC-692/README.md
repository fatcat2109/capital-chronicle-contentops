# CC-692 standing public-output sweep

The existing Publisher-B lane runner owns the six-hour cadence. After integration, return CC-692 to `Owner: Codex Publisher-B` and set it `OPEN` for its first due run. `Order: first` items take precedence. The sweep uses the CC-639 readback and CC-690 decision checks.

1. Run `python -B scripts/run_day_readback.py --sweep --output-dir <run-evidence-folder>` from the installed ContentOps root. Use a dated folder under the lane's existing evidence directory. `day_readback.json` records the 24-hour interval, each platform's copy and verification counts, the exact readback targets and grouped defects. `decision_checks.json` contains the CC-690 results.
2. For `sweep.readback_targets`, use the existing destination readback on each dispatch ID. The readback-only command is `python -B scripts/run_native_neo_executor.py readback --binding <existing-readback-binding> --dispatch-id <exact-id>`. Complete any returned readback request on its bound identity. For Telegram use the official public channel only. The Notes dispatch from CC-584 remains on the watch list outside the 24-hour interval while it is uncertain. A public page with no exact matching Note leaves `UNKNOWN_WRITE` in place.
3. Refresh the report in the same evidence folder using `--sweep-started-at <started_at_utc from the first pass>`. The report distinguishes public page reads, exact receipts refreshed during the sweep, retained receipts and gaps. Record any destination access failure with the dispatch ID and exact cause. Zero tracked copies on a platform means the store and publication feed held no copies in the sweep cohort.
4. Choose one actionable group from `sweep.defect_groups`. Check the backlog for the same cause and route before choosing. Fix it on a branch and hand it to the first stream, or append one `PROPOSED` item with the decision, route, exact dispatch or public URL, and evidence path. Record a clean or already-covered result if there is no new actionable group.
5. Write one dated `Result` line on CC-692 with the window, what was checked, the fix or filed item or first access cause, and the evidence path. Set `Status: OPEN (next due <d MMM yyyy HH:mm> GMT+7)` using the report's `next_due_utc` converted to GMT+7. The existing runner takes the next eligible sweep.

The sweep command issues only allowlisted public GETs and opens the publication store in SQLite read-only mode. Any exact transport follow-up uses the existing readback owner. A sweep never invokes a publish, edit, delete, retry or deploy operation.
