## Rules that change the implementation choice

- MiniBench/seasonal bot questions normally have a three-hour window and one
  forecast per question. Human tuning on open/upcoming tournament questions,
  hand-copying a forecast into the tournament, and rerunning an unwanted forecast
  are incompatible with its no-human-in-the-loop rules. This rehearsal used an
  ended round and makes no prediction-quality or leaderboard claim.
- Comments are required. The documented atomic
  `/api/questions/bulk-forecast-comment/` request can bind the forecast and private
  explanation together. A rejected atomic request saves neither; an ambiguous
  network return still needs the existing publisher's readback before any retry.
- Market Pulse Q4 2026 explicitly permits a bot, with one entry as a bot or a
  person. Its rolling numeric groups use spot scoring at each close. It asks for
  futures return spreads, yields and other numeric targets; the desk's current
  spot/plan probabilities are not interchangeable with those distributions.
- API access requires authentication and may return hidden fields as `null`.
  Underlying question IDs are distinct from post IDs. No missing field, resolver,
  scale, option or distribution is inferred from a community forecast or outcome.
- The general API/terms rules separately restrict commercial use and AI/ML
  development/evaluation. The updated terms do not grant general automated
  website collection. Future question acquisition must use an allowed official
  interface under its applicable terms. The existing local question observations
  are retained for this mapping rehearsal; they are not redistributed in this delivery.
