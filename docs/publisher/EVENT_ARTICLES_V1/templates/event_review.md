# Event review: writer brief

Use `article_type: EVENT_REVIEW` as a subtype of the existing editorial mode.
This is an editorial brief for the approved writer, not canned reader-facing prose.

Light preparation supplies the immutable pre-event scenario version, original
probabilities and cutoff, admitted event outcome, correctly dated reactions, and
CC-106's actual score and baseline comparison when available and public-safe.
Keep the pre-event forecast separate from later observations and revisions.

Put the supplied `Retrospective analysis, written on <day month year> (ET)` line
before the review body. Its date comes from the actual writing instant converted
to America/New_York, including daylight saving; never use the event's date as the
writing date. Keep this own writing-clock notice outside `event_article_packet.copy`
and its source-fact `numeric_bindings`.

CC-338 (G06): reproduce the preview's full SHA-256 and freeze time in ET. The
transport attaches the original frozen public file as a download and verifies the
download's hash and length. Never recreate it from prose or re-serialize its JSON.
Include the entire supplied public-call scorecard table, with its total count and
every triggered, not-triggered, invalidated, withdrawn and unresolved call. Keep
the original wording. Numerical scores and naive-release-beta comparisons come
from Main's scored output. A public state or a fill is not a performance score.
Do not claim returns or skill (decision 84). Missing scores limit that comparison;
they do not remove any call from the denominator.

The native Sol 6.1 MAX writer authors the following `copy` sections:

| Key | Reader question |
| --- | --- |
| `headline` | What did this event teach us? |
| `dek` | Which expectation mattered, and what changed? |
| `what_happened` | What did the admitted source report, in its original units and period? |
| `scenario_match` | Which frozen branch occurred, or why was the outcome unmodelled? |
| `what_moved_when` | Which market moved first, over which observed window, and did it break the frozen pre-event range? |
| `forecast_score` | What did CC-106 actually score, using which metric and sample? |
| `consensus_comparison` | How did the forecast compare with the consensus-only baseline? |
| `prediction_market_comparison` | How did it compare with the market-only baseline? |
| `market_reactions` | What actually moved across rates, the dollar, gold, oil, indices and exposed sectors? |
| `lesson` | What was wrong, what remains uncertain, and what should change in the next research view? |
| `disclaimer` | This is general market analysis, not financial advice. |

`market_reactions` has exactly `rates`, `dollar`, `gold`, `oil`, `indices` and
`sectors`. Separate first-hour from first-day windows and observed price changes
from causal inference. A partial window is not a completed daily reaction. A hit
branch is not proof of alpha, a correct trade, or sufficient calibration.

Use the original preview and its range without retrospective replacement. Name
the release clock and each observation window in New York time, written ET.
Separate the admitted outcome, measured reaction and causal interpretation. A
missing market window or score limits that claim, not the rest of the review.
Never backfill a preview with post-event data or invent a range break.

Code and Main own scoring, numerical estimates and attribution. Never calculate a
Brier score, log score, error, surprise or probability in prose. Do not revise the
forecast after the outcome. Main's computed scores and estimates may be public
under decision 72 b, labelled Capital Chronicle model estimates with decision 40's
notices. Raw restricted vendor tables stay private for redistribution rights.
If CC-106 or a baseline is absent after searching held outputs, omit the unsupported
comparison, retain the gap internally and publish the supported review.

Use natural source attribution, a serious countercase and a useful lesson. This
format permits decision 40's structured, impersonal conditional calls and scores the earlier calls using Main's admitted output. Each
call carries its condition, direction, horizon and invalidation, "Analysis, not
financial advice." and "Capital Chronicle may hold positions in the markets it
covers." Use the optional root `conditional_calls` array and include
`conditional_call_text(call)` verbatim in authored copy; the event checker applies
the shared `check_publication_copy` gate. Unconditional calls, sizes, profit
targets, DEMO, account, order and position details and prediction-market numbers remain excluded on every surface.
Kalshi odds stay in words only. Bind every numeric span to the exact admitted
source display in the private record.
