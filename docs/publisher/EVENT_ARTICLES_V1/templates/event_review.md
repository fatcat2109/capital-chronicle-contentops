# Event review: writer brief

Use `article_type: EVENT_REVIEW` as a subtype of the existing editorial mode.
This is an editorial brief for the approved writer, not canned reader-facing prose.

Light preparation supplies the immutable pre-event scenario version, original
probabilities and cutoff, admitted event outcome, correctly dated reactions, and
CC-106's actual score and baseline comparison when available and public-safe.
Keep the pre-event forecast separate from later observations and revisions.

The native Sol 6.1 MAX writer authors the following `copy` sections:

| Key | Reader question |
| --- | --- |
| `headline` | What did this event teach us? |
| `dek` | Which expectation mattered, and what changed? |
| `what_happened` | What did the admitted source report, in its original units and period? |
| `scenario_match` | Which frozen branch occurred, or why was the outcome unmodelled? |
| `forecast_score` | What did CC-106 actually score, using which metric and sample? |
| `consensus_comparison` | How did the forecast compare with the consensus-only baseline? |
| `prediction_market_comparison` | How did it compare with the market-only baseline? |
| `market_reactions` | What actually moved across rates, the dollar, gold, oil, indices and exposed sectors? |
| `lesson` | What was wrong, what remains uncertain, and what should change in the next research view? |
| `disclaimer` | This is general market analysis, not financial advice. |

`market_reactions` has exactly `rates`, `dollar`, `gold`, `oil`, `indices` and
`sectors`. Separate first-hour from first-day windows and observed price changes
from causal inference. A partial window is not a completed daily reaction. A hit
branch is not proof of alpha, a correct trade, or sufficient calibration.

Code and Main own scoring, numerical estimates and attribution. Never calculate a
Brier score, log score, error, surprise or probability in prose. Do not revise the
forecast after the outcome. A score derived from private consensus or unlicensed
market data stays private unless the existing rights owner permits public reuse;
renaming it as a comparison does not change its rights. If CC-106 or an admitted
baseline is missing, preserve the internal blocker and avoid a fabricated comparison.

Use natural source attribution, a serious countercase and a useful lesson. Keep
trading calls, entries, stops, targets, sizes, account details, DEMO positions/results
and buy/sell instructions out of copy, tables, charts, captions and derivatives.
Bind every numeric span to the exact admitted source display in the private record.

Apply the current media standard and the same actual native Sol 6.1 MAX writer's
edit, final desktop/mobile render inspection and repair. Light prepares; Luna filters
genuine X input only. Record every actual model call and distinguish configured
from observed model/effort. Reuse the existing source/story, review and media owners.

Run the CC-107 public-output guard on all copy and changed derivatives. A passing
guard supplies no rights decision, media acceptance or publication grant. Every
article of this new type needs Jim's explicit yes until a standing yes exists;
publication then uses the sole existing canonical-first publisher and readback.
